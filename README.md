# AI-HR-Selection

# Теоретическая часть проекта «AI-HR-Selection»

## 1. Хранение и структура данных
Для обеспечения гибкости и скорости разработки на этапе *MVP данные хранятся локально в директории 'data'. Хранилище организованно по принципу 
реляционной структуры данных (схема «звезда/один-к-одному»), где ключевые сущности сопоставляются по идентификатору.

Источники данных:
Для обучения и тестирования модели на этапе разработки MVP использовались синтетические данные:
​Генерация через LLM: Текстовая часть резюме (resumes.csv) была сгенерирована с помощью нейросетевых моделей (GPT-4) с целью имитации реальных профилей кандидатов для различных профессий.
​Структурированные атрибуты: Файл candidates.json сформирован алгоритмически на основе сгенерированных резюме для обеспечения связности данных и соответствия формату id.
​Служебные фильтры: Список стоп-слов (stopwords.txt) сформирован на основе открытых лингвистических библиотек для русского языка (nltk/spacy) для обеспечения чистоты предобработки текста.
*MVP (Minimum Viable Product) - это стадия разработки, когда создаётся минимально жизнеспособная версия продукта, которая уже выполняет ключевые функции, но при этом реализована максимально просто и быстро.
## 2. Схема связей данных
- Основная таблица (Резюме): Файл resumes.csv выступает в качестве центральной таблицы, содержащей текстовую информацию.
- Дополнительная таблица (Навыки): Файл candidates.json дополняет профиль кандидата структурированными тегами.
- Связь: Сущности resumes и candidates логически связаны между собой связью «один-к-одному» (1:1) по первичному ключу id.

## 3.  Подробное описание структуры и типов данных
- Таблица resumes.csv (Структурированные текстовые данные):
  - id (Integer, Primary Key) - уникальный идентификатор соискателя.
  - text (String / Text) - сырой текст резюме для последующей векторизации (TF-IDF).
  - label (String / Categorical) - целевой класс (профессия) для обучения модели.

- Документ candidates.json (Слабоструктурированные данные) 
Представляет собой массив объектов (словарей), где для каждого кандидата хранится подмножество признаков:
  - id (Integer, Foreign Key) - идентификатор для связи с таблицей резюме.
  - skills (List of Strings / Array) - массив текстовых тегов, отражающих ключевые навыки (проходит бинаризацию через MultiLabelBinarizer).
  - label (String) — категория (дублирующий/проверочный признак).

- Словарь stopwords.txt (Служебный плоский файл)
  - Текстовый файл, где каждая строка содержит ровно одно строковое значение (String) — стоп-слово. Используется как конфигурационный фильтр при сборке признаков.

В процессе работы программы (на этапе предобработки) данные из CSV и JSON динамически объединяются (операция merge) по ключу id в единую плоскую матрицу признаков для передачи в классификатор Random Forest.

## 4. Согласие клиента
Для обработки персональных данных требуется **согласие клиента** в соответствии с законодательством о защите данных.  

## 5. Модель машинного обучения
Выбрана модель **Random Forest** в ансамбле с NLP‑признаками.  
- **Плюсы**: устойчива к шуму, хорошо работает с табличными признаками, легко интерпретируется.  
- **Минусы**: хуже обрабатывает чистый текст без качественных признаков, может быть медленной при большом числе деревьев.  

## 6. Метрики
Для оценки качества модели используются:  
- **Accuracy** (Доля правильных предсказаний)
- **Precision** (точность) 
- **Recall** (полнота)  
- **F1‑score** (сбалансированная метрика)  

## 7. Последовательность шагов
1. Получение заявки от HR  
2. Загрузка данных (резюме и навыки)  
3. Предобработка текста (очистка, TF‑IDF)  
4. Генерация признаков из JSON (навыки)  
5. Объединение признаков  
6. Обучение модели Random Forest  
7. Оценка метрик  
8. Вывод результатов  

## 8. Интеграция в процессы HR и выгоды от внедрения
Разработанная система может быть встроена в существующие HR‑процессы через интеграцию с системами управления персоналом (ATS - Applicant Tracking System, например Workday, SAP SuccessFactors, Greenhouse).
- Входные данные: рекрутер загружает резюме или система автоматически получает их из ATS.  
- Обработка: модель анализирует текст резюме, навыки и цифровой след, формирует рейтинг кандидатов. 
- Выходные данные: рекрутер получает список кандидатов, отсортированный по релевантности, с пояснением ключевых факторов (например, совпадение навыков, опыт работы).
- Взаимодействие: HR-специалист может вручную корректировать результаты, добавлять обратную связь, которая используется для дообучения модели.
Выгоды:
  - Сокращение времени на первичный отбор (экономия ресурсов).
  - Снижение субъективности и человеческого фактора.
  - Повышение качества найма за счёт более точного сопоставления навыков и требований.
  - Возможность аналитики: какие источники кандидатов наиболее результативны, какие навыки чаще встречаются у успешных сотрудников.

## 9. Ограничения и риски
Несмотря на выгоды, внедрение системы несёт ряд рисков:
- Этические: возможная дискриминация по полу, возрасту, национальности, если данные содержат скрытые биас‑факторы.  
- Юридические: необходимость соответствия законам о защите данных (GDPR, ФЗ‑152 в России). Нарушение может привести к штрафам.
- Технические: низкая точность при малом объёме данных, несбалансированные классы, ошибки в исходных резюме.
- Организационные: сопротивление сотрудников внедрению ИИ, недоверие к автоматическим решениям.

## 10. Способы снижения риска
Для минимизации рисков предлагаются следующие меры:
- Этические: регулярный аудит модели на предмет дискриминации, использование explainable AI (SHAP, LIME) для прозрачности решений.
- Юридические: хранение согласия кандидатов, возможность удаления данных по запросу, шифрование и контроль доступа.
- Технические: увеличение объёма обучающих данных, балансировка классов, добавление новых признаков (например, опыт в годах, сертификаты).
- Организационные: обучение HR‑специалистов работе с системой, предоставление возможности ручной корректировки и апелляции кандидата.
